# Locant v0.9: the release candidate

**Status:** Spec written Sep 29, 2026, from the evaluation of 0.8.1 against a public 1.0.
**Scope of this spec:** everything a stranger's Mac needs before 1.0 that code and repository can provide: a build that runs on every push, an app bundle that opens offline, a Homebrew cask, a diagnostics block for issues, the public-repo files, honest copy on every surface, and a way for outside testers to report. Version 0.9.0, tag `v0.9.0`. What 0.9 is for: feedback from Macs that are not Malik's. 1.0 is decided after that feedback, not by this spec.
**Out of scope:** in-place updates (R74 records the decision and the manual path stays); any new capture feature; localization (English only, stated); matching agent apps by name for paste (R63 forbids it); splitting `AppState.swift`; submitting the cask to homebrew/homebrew-cask (its notability bar is 75 stars or 30 forks; a tap under Malik's account serves until then).

Read `CLAUDE.md`, then `specs/v0.8.1.md` and `specs/v0.8.1-paste.md`. Nothing here changes the capture flow, the schema, or the MCP server. PRD §3.6 "Lightweight by design" and the no-telemetry rule hold: the diagnostics block (R70) is text the user copies and pastes by hand, never sent.

## 1. What is wrong today

| Gap | Today | Why 1.0 cannot ship over it |
|---|---|---|
| No outside use | 1 star, 21 downloads across every release, 0 issues; never run on macOS 15, Intel, a non-notched Mac, or a non-English locale | 1.0 promises it works on other Macs; there is no evidence |
| No CI | Build and tests run on Malik's Mac only | A public repo taking issues and PRs needs a green check on push |
| App not stapled | `scripts/release.sh` staples the dmg only; `/Applications/Locant.app` has no ticket | A first launch offline after drag depends on Gatekeeper's online lookup |
| No cask | `brew install --cask locant` finds nothing | Developers expect it; the asset name `Locant.dmg` has no version and no sha |
| Manual updates, unstated | The alert says download and drag; the README says nothing about it | Silence reads as a bug; a stated manual update is a choice |
| Stale copy | Site "as of version 0.7.2"; README "123 tests" (179 run); PRD "Draft v0.5", "MCP server in TypeScript"; schema `$id` under a GitHub account that does not exist | A 1.0 is read closely |
| No public-repo files | No CHANGELOG, CONTRIBUTING, SECURITY, no uninstall instructions | Uninstall leaves TCC grants, a defaults domain, a folder, and three agent configs behind |
| Tag naming | `publish.sh` derives `v1.0` from `1.0.0` | Malik wants `v1.0.0`; the checker parses both, the rule should be one |
| Nothing helps a stranger file an issue | The bug form asks for version, macOS, and chip by hand | A block the user copies from Settings answers every triage question at once |
| Loose ends | `Locant/Capture/FrozenFrame.swift` is an empty file outside the project | Reads as neglect |

## 4. Requirements

**R66. Version 0.9.0.** `MARKETING_VERSION = 0.9.0`. `Locant/Capture/FrozenFrame.swift` (empty, not in the project) is deleted.

**R67. CI.** One workflow, `ci.yml`, on push to `main` and on pull requests: `macos-26` runner, Xcode 26 selected, `xcodebuild -project Locant.xcodeproj -scheme Locant -destination 'platform=macOS' test` with ad hoc signing (`CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual`), the same line a contributor runs. A second job validates `schema/capture.schema.json` as JSON and runs `scripts/check-skill.sh`'s static half when it can (the skill's command needs the app; the frontmatter checks do not). No secrets, no signing, no release from CI: releases stay on Malik's Mac where the Developer ID and the notary profile live. As the test host the app skips the two permission alerts: on a runner nobody clicks Continue, and the tests are over pure functions.

**R68. The app is stapled.** `release.sh` builds, verifies, zips the app with `ditto -c -k --keepParent`, submits the zip to the notary service, staples the app, then packages the dmg from the stapled app, signs, submits, and staples the dmg. Both `xcrun stapler validate` calls pass before the script prints Done. Without a notary profile the script still builds and packages, says what it skipped, and the dmg is not to be published (`publish.sh` already refuses an unstapled dmg).

**R69. Homebrew.** `publish.sh` uploads two assets: `Locant.dmg` (the unversioned name the site and the update alert use) and `Locant-<version>.dmg` (what a cask must point at, since a cask's url has to change with the version). It prints the sha256. Tags are always `v<MARKETING_VERSION>` in full (`v0.9.0`, `v1.0.0`); the `.0` shortening ends, and the tags that exist keep their names. `scripts/cask.sh` renders `packaging/homebrew/locant.rb` with the version and sha of `build/release/Locant-<version>.dmg`; the cask declares `depends_on macos: ">= :sequoia"`, `app "Locant.app"`, a `zap` stanza naming the defaults domain and saved state, and nothing else (the captures in `~/Pictures/Locant`, the TCC grants, and the agent configs are the user's; the README says how to remove them). The tap is `Malik1942/homebrew-locant` with `Casks/locant.rb`; the README shows `brew install Malik1942/locant/locant`.

**R70. Diagnostics, pure.** `Diagnostics.render(_ values: Diagnostics.Values) -> String`: a Markdown block, one line per fact, in this order: Locant version and build, macOS version, chip (arm64 or x86_64), whether the process is translated under Rosetta, displays (count, and each one's size in points and scale), Accessibility and Screen Recording grant states, the app's path (which says whether it runs from `/Applications` or from a build folder), the Point hotkey and the five action hotkeys, the ball and auto-hide switches, taps and sounds, paste into agent, iterations, retention days, capture folder (with the home directory replaced by `~`), organization, the number of captures in the folder, which agents are connected, checks for updates and the last check date. Nothing about the user beyond the home folder path shortened to `~`; no capture content. `Values` is a struct built by `AppState`; the renderer has no AppKit import and is tested for format, for the `~` substitution, and for a missing value ("unknown") in every optional slot.

**R71. Copy diagnostics.** Settings › General, in the section with the version: a **Copy Diagnostics** button under Check Now… whose label reads "Copied" for two seconds after the click, like the snippet button in Agents. The bug issue form gains a "Diagnostics" textarea that says where the button is; the version, macOS, and chip fields it replaced are gone.

**R72. Public-repo files.** `CHANGELOG.md`: one section per release from 0.6.0 on, from the release notes on GitHub, newest first, with dates; 0.9.0 at the top. `CONTRIBUTING.md`: how to build, run the tests, the one-spec-at-a-time rule, what an issue needs, that PRs follow a spec or fix a filed bug, no third-party packages. `SECURITY.md`: what Locant touches (Accessibility, Screen Recording, the clipboard, `~/Pictures/Locant`, three agent config files), what it never does (network beyond the release check, telemetry), and to report privately by email rather than in an issue. README gains **Uninstall**: quit, delete the app, then optionally `tccutil reset Accessibility com.malikzhang.deixis` and `tccutil reset ScreenCapture com.malikzhang.deixis`, `defaults delete com.malikzhang.deixis`, delete `~/Pictures/Locant`, Disconnect in Settings › Agents before quitting or remove the `locant` server from the three config files by hand, and `brew uninstall --zap locant` when installed by Homebrew.

**R73. Copy.** Site: the agents lede says "as of version 0.9.0", the ribbon says "now v0.9.0", the footer says 0.9.0, and the Gemini CLI row stays Untested until someone tests it. README: the test line no longer states a number ("the tests over the pure functions"); the Works-where-you-paste dates stay, they are true. PRD header: status "Living document; the specs in `specs/` are the record", platform "Swift 6, the MCP server inside the app (`Locant --mcp`)". Schema `$id` becomes the raw URL on `main` under the account that exists, `https://raw.githubusercontent.com/Malik1942/locant/main/schema/capture.schema.json`, which resolves.

**R74. Updates stay manual, and say so.** The README's Install step and a line in the Updates row of the feature table say: Locant tells you about a new version and opens the download; you drag it over the old copy; there is no in-place update, and the permissions carry over. The alert text already says this. In-place update is a 1.0 decision, recorded here: with no third-party packages it means a replace-and-relaunch of Locant's own, about a day, tested only across two real releases.

**R75. Outside testers.** `.github/ISSUE_TEMPLATE/tester.yml`, "I tried it on my Mac": the diagnostics block, which steps of `docs/rc-checklist.md` passed, what did not, and one free text field. `docs/rc-checklist.md`: fifteen steps in order, from install and the two permissions through Point in a native app, in the Simulator when present, in a web page, drag, Shift set, Option, Snap, Text, Color, Cut, MCP with one agent, Check Now, quit and relaunch, uninstall. Each step says what to look for. The README's Works-where-you-paste section links the form: "Ran it on a Mac that is not mine? The tester form takes two minutes."

## 5. Tests

- `DiagnosticsTests`: the block's line order; `~` replaces the home directory in the capture folder; a nil grant, display list, or last check date renders as "unknown" or "never"; the arm64 and Rosetta lines.
- The existing 179 tests pass; the CI workflow runs them.
- By hand, before tagging: Settings › General shows Copy Diagnostics in both appearances; the copied block opens in TextEdit with every line present; `scripts/release.sh` ends with two "The validate action worked!" lines; `scripts/cask.sh` renders a cask whose sha matches `shasum -a 256` of the dmg.
