# Locant: the component and source line of a web element

**Status:** Built Nov 13, 2026, on `am/locant-html-scraping-comparison-4ba746` (PR #87); not merged, not released. Started Nov 4 as a Chrome-only prototype, after Malik compared a Locant capture with Claude Code Desktop's Browser picker on bricks-build (`localhost:5176`): the picker gave `<Card />`, its props, `Source /src/Library.tsx:150:39` and `Rendered at :92:24`; Locant gave `#caption-g2 · .card-caption`. Accessibility publishes the DOM's id and classes, never what React keeps on the node. Measured Nov 3: React 19 keeps `_debugOwner` and `_debugStack` on every fiber in development, and the dev server's source maps turn the stack's frames into the picker's lines. On Nov 13 Malik asked for it shipped in the picker's format and for every mainstream browser, Dia first (in his retained captures, 20 web captures came from Dia, 14 of them on localhost, and none from Chrome). R146–R150 are the prototype's, revised here; R151–R156 are new.
**Scope:** a Point capture of one web node, on a page a dev server on this Mac serves, in Google Chrome, Dia, Microsoft Edge, or Brave.
**Out of scope:** Safari and Arc (§5), Firefox and Claude's Browser pane (no way to ask, §5), Shift sets, drawn frames, frameworks other than React, the source line of an element a server component rendered, and pages from anywhere but this Mac.

This spec changes two earlier requirements. `specs/settings-cleanup.md` R91 allowed one group header in Settings, Agents' "MCP"; Captures now has a second, "Web pages" (R155). `SECURITY.md` and the README said Locant's only network request was the daily update check; it now also reads a local page's source maps from the dev server on this Mac (R152).

## 1. Requirements

**R146. Ask the page.** When a Point click locks a web node (`dom` is present) on a local page (R151) in a browser Locant can ask (R153), Locant starts one lookup at once, beside the crop. It runs `osascript`, which finds the window whose front tab's URL starts with the capture's URL without its fragment, and runs a script there. Nothing waits for it until Enter.

**R147. The script.** `web-source.js` finds the DOM node by its id; else, from the accessibility frame converted to a client point, the node under the point whose class list matches; else the node under the point whose size matches the frame best; else, by classes alone, the one whose size and place match best. The client point comes from the page's viewport on screen, which Locant reads through accessibility: the scroll area holding the outermost web area under the click. The window's own numbers are the fallback only, because they are wrong beside Dia's sidebar and Edge's inset page, and Brave randomises them. From the React fiber on the node (or the nearest ancestor that has one) the script reads: the owner chain's component names, a server component by the name on its record; the nearest owner's props (values shortened, `children` left out, a server component's left out whole); and, for the element and for its owner, either `_debugSource` or the first eight frames of the stack React recorded where the JSX ran. It returns one JSON string.

**R148. The page's own world.** Chrome, Edge, Brave and Dia run Apple Event JavaScript in an isolated world, where React's properties on the DOM nodes are not visible. The script runs in the page's world through a script element, added and removed in one step, and returns its answer in a DOM event with a random name. A page whose Content-Security-Policy forbids inline scripts answers with an error, and the capture has no component. A browser measured not to isolate would get the script directly, with no element (`WebBrowser.isolates`).

**R149. At Enter.** The capture waits at most 1.5 s for the lookup; an answer that comes later is dropped. The Apple Event itself may run 10 s. For a localhost page, server paths (`/src/Library.tsx`) become absolute paths under the folder the listening process runs in, when the file is there.

**R150. In the payload.** The element gets `component` (`schema/capture.schema.json`). The markdown shows, after the element's head line: `Component: Card in Grid › Library › Routes › Page › … (React, read from the page)`, `Props: …`, `Source: <file:line:col> (this element's JSX)`, and `Rendered at: <file:line:col> (where <Card> is used)`. A Source line replaces the "Grep the class names" advice. Two rows of one list share Source and Rendered at; their ids, labels and frames tell them apart. Every failure leaves the capture as it was.

**R151. Local pages only.** A page is asked only when its host is `localhost`, `127.0.0.1`, `::1`, or ends in `.local`: the rule that makes a web capture a fix (`ModeInference.isLocalhost`). Any other page is someone's production build, with nothing to read but shortened names, and Locant sends it nothing.

**R152. Source maps are read in Locant.** The script fetches nothing. Locant fetches each built module a stack frame names, and its map, from the dev server the page came from, and from nowhere else: only `http` and `https` addresses on a local host, and for webpack only chunks on the page's own host and port. It reads flat maps, inline (`data:`) or beside the module; the sectioned index maps Turbopack writes; and webpack's eval maps, where each module is a string in a chunk, evaluated under a `webpack-internal:` name, with its map inline just before that name. The frame used is the first that is not React's own: the JSX runtime's frame is recognised by its function (`jsxDEV`, `jsx`, `jsxs`, `createElement`), since bundlers put it in the app's own chunk, and a source the map lists in `ignoreList`, or under `node_modules`, is passed over. A module with no map is its own source. A map's source becomes a path: a `file://` address or an absolute path as it is, a `webpack://` or `turbopack://` name by the path after its namespace, anything else relative to the module's address. Nothing is cached between captures, so an edited module is read again.

**R153. The browsers.** One table (`WebSourceLocator.browsers`) names each browser Locant can ask: its bundle ids, which Apple Event it takes, what the user turns on in it, and a phrase only its refusal contains. A browser is in the table only after both its answer and its refusal have been read from a real install; no browser's words are assumed from another's. Read on Nov 13, 2026:

| Browser | Asked with | The user turns on | Its refusal |
|---|---|---|---|
| Google Chrome 157 (stable, beta, dev, canary) | `execute <tab> javascript` | View › Developer › Allow JavaScript from Apple Events | `Executing JavaScript through AppleScript is turned off. … (12)` |
| Microsoft Edge 157 | the same | the same menu path | the same sentence, error 12 |
| Brave 1.99 | the same | the same menu path | the same sentence, error 12 |
| Dia 1.57.1 | the same; the reply comes back as a JSON string and is unwrapped | nothing in Dia: it must be started with `--enable-applescript-javascript` | `JavaScript execution via AppleScript requires the --enable-applescript-javascript launch flag. (-10006)` |

**R154. No prompt in a capture.** macOS asks once per browser whether Locant may send it Apple Events. At the click Locant asks macOS, without prompting, where that stands (`AEDeterminePermissionToAutomateTarget`); when the user has not been asked, or said no, the lookup does not run. A capture that got no component for a reason Settings can fix (not asked, denied, the browser's door closed) shows one hint after its own toast, at most twice per browser: "Locant can name the component and source line here · Settings › Captures › Web pages".

**R155. Settings › Captures › Web pages.** One row per installed browser in the table, a title and one status or button; the group is absent when none is installed. Not open: "Not open", or for Dia a button, Open Dia, which starts it with its flag. Not asked: Allow…, which raises macOS's prompt. Denied: Grant…, which opens Privacy & Security › Automation. Door closed: for Chrome, Edge and Brave the menu path as the status; for Dia a button, Reopen Dia, which quits it and starts it with the flag (Dia restores its tabs). Ready: a green tick and "Ready". Each row's tooltip says what it is for. The status is found by asking the browser to work out `0` in its front tab, every 2 s while Settings is open and the browser is not ready; a ready browser is not asked again.

**R156. What went wrong.** Each lookup that gives no component writes its reason to the log (`com.malikzhang.deixis`, category `web-source`, public). Settings › General › Diagnostics gains a line after Last failure: `Web source: <browser> · <what the page gave, or why it gave nothing> · <time>`, or `not asked since launch`.

In Chrome (6 captures) and in Dia (3), two different cards' captions each gave `Component: Card in Grid › Library › Routes › Page › …`, the same `Source: …/bricks-build/src/Library.tsx:150:7` and `Rendered at: …/Library.tsx:93:24`, under different ids and frames. In Dia, three elements with no id, found by their place beside the sidebar: two cards' `link · .card-tile` gave Source `:136:9` and Rendered at `:93:24`; a `staticText` with no identifier gave `Masthead in Library › Routes › Page › App`, Source `:83:9`, Rendered at `:47:9`. - Geometry, Nov 13: in Chrome, Edge, Brave and Dia the scroll area holding the web area is the viewport to within a point, at two scroll positions; an element's accessibility frame minus that origin is its client rectangle.

## 4. Decided with Malik, Nov 13

- The first capture after install: no prompt in a capture, Settings rows, a hint; no late fill of the sidecar (R154, R155).
- The browser's switch: recognised from the refusal, named in Settings (R153, R155). Locant does not turn it on itself.
- The synchronous XHR is gone (R152). The script element stays, on local pages only (R148, R151).
- Every mainstream browser was asked for; §5 says where each stands.

## 5. Not in this release

- **Safari.** It has the command (`do JavaScript … in <tab>`), and its refusal was read: `You must enable 'Allow JavaScript from Apple Events' in the Developer section of Safari Settings to use 'do JavaScript'. (8)`. Its answer has not been read, because that setting needs the user's password. Not in the table until it has.
- **Arc.** Its dictionary has `execute … javascript` and its binary an Allow JavaScript from Apple Events setting, but Arc 1.173 opens only to a sign-in, so neither its answer nor its refusal was read.
- **Firefox.** No scripting dictionary at all (Firefox 160). A browser extension or a build plugin in the user's project are the only doors; each is its own project. An extension would also remove Dia's flag and every per-browser switch.
- **Claude's Browser pane.** No way to run a script in it from outside.
- **Dia's flag** is lost at every quit and update; Locant can say so and reopen Dia, not make it stay.
- The source line of an element a server component rendered (its stack names the server's built file); Shift sets and drawn frames; Vue, Svelte and other frameworks; dev servers reached by a LAN address or a custom host.
